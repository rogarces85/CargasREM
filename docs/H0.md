## T-004 — POC lectura Excel (PhpSpreadsheet 5.10) ✅

**Script:** `poc/lectura_excel.php` · **Estado:** PASÓ

Ejecutado con PHP 8.2.12 CLI. Genera fixtures sintéticos en `poc/fixtures/` (con y sin caché de fórmulas, formatos `.xls` / `.xlsx` / `.xlsm`) y verifica:

1. **`setReadDataOnly(true)` + `IReadFilter`** (ventana A1:H20): lectura correcta por coordenada en los 3 formatos. Valores: texto encabezado, año, 1 decimal (67.5), >1 decimal (1234.567), celda vacía (`null`).
2. **Caché de fórmulas**: en modo `dataOnly`, `getValue()` devuelve la fórmula (`"=B14*2"`) y **`getOldCalculatedValue()` devuelve el valor cacheado del archivo** (30) — esta es la API correcta para leer valores "como Excel los dejó" sin recalcular en PHP.
3. **LIM-001 (fórmula sin caché)**: regla de detección = `getValue()` empieza con `=` **y** `getOldCalculatedValue() === null` → rechazo con mensaje estandarizado ("Abra y guarde el archivo en Excel para calcular fórmulas"). Funciona para `.xlsx`/`.xlsm`.

### Hallazgos T-004 (para decisión H0)

- **BIFF8 (.xls) NO puede almacenar fórmula sin resultado**: el writer `Xls` fuerza `0.0` como valor aunque se pida `setPreCalculateFormulas(false)`. Consecuencia: la detección estricta de "fórmula sin caché" (oldCalculated === null) **solo aplica a `.xlsx`/`.xlsm`**. Riesgo residual bajo: los `.xls` del flujo REM son generados/guardados por Excel (que siempre memoriza resultados al guardar); el escenario "sin caché" ocurre solo con archivos generados por software externo.
- PhpSpreadsheet 5.10: `setPreCalculateFormulas(bool)` es el método del writer Xlsx (no `setPreCalculationEnabled`).
- El ReadFilter reduce memoria en archivos reales grandes (los sintéticos son chicos: `dims A1:D17` sin y con filtro).

## T-005 — POC escritura COM/ACE sobre copia de MASTER.mdb ✅

**Script:** `poc/com_escribe.php` · **Estado:** PASÓ

1. Copia `BD/MASTER.mdb` → `storage/rem/poc/MASTER_poc.mdb` (original intocado; hash SHA-256 pre/post idéntico: `f9733be2…`).
2. Conexión **ADODB + Microsoft.ACE.OLEDB.12.0** (64-bit, registrado fuera de WOW6432Node) desde PHP 8.2 64-bit con `com_dotnet`. Fallback a 16.0 implementado (no fue necesario).
3. Estructura verificada: tablas `Datos` (56 col.), `DatosC`, `Registros` (`ano | CantReg | Fecha | idservicio | Mes | Serie`).
4. **INSERT parametrizado de 2 filas** en `Datos` (ADODB.Command + Parameters): OK.
5. SELECT de vuelta: **match exacto en todo** — texto con acentos/ñ (`POC-T-005-F1-ÁÉÍÓÚÑ`), decimales (`1000.125` vuelve como `double`), enteros Long, y `fechaIngreso` adDate.
6. DELETE de las filas de prueba → 0 restantes. La copia queda limpia.

### Hallazgos T-005 (reglas para el motor de carga)

- **`adDate` (fechaIngreso) exige variante fecha**: pasar string 'Y-m-d H:i:s' como parámetro de tipo 7 falla ("valor de tipo no válido"). Solución: `new VARIANT($fecha, VT_DATE)`.
- **El parámetro no puede ser más grande que el campo** ("el campo es demasiado pequeño"): con `adVarChar`, `Size` del parámetro ≤ largo del campo.
- **Esquema real de `MASTER.mdb → Datos` (56 col.)**:
  | Campo | Tipo ADO | Observación |
  |---|---|---|
  | `Ano` | Long (Integer) | NOT NULL |
  | `CodigoPrestacion` | VarChar(50) | NOT NULL |
  | `Col01..Col50` | Double (prec 15) | NULL permitido |
  | `fechaIngreso` | adDate | NULL |
  | `IdEstablecimiento` | VarChar(**7**) | NOT NULL — código establecimiento sin guion |
  | `IdServicio` | VarChar(**2**) | NOT NULL — ¡al contrario de la base serie, que lo guarda como Long! |
  | `Mes` | Long | NULL |
- ⚠️ DIFERENCIA HALLADA: en la **plantilla** `MASTER.mdb`, `Datos.IdServicio` es **VarChar(2)**; en `DatosSERIEBM2025.mdb`, `Datos.IdServicio` es **Integer(Long)**. El consolidador que vuelca staging → archivo Minsal debe castear.
- DEC-POC-01: los `ColNN` se pasan siempre como **float nativo de PHP** (los strings tipo "1234,56" con coma fallan coercion; la normalización coma→punto de RN-037 se aplica en el mapeador, antes del parámetro).
- Detalle de la plantilla: mezcla de mayúsculas/minúsculas en nombres (`Col01`..`Col41`, seguido de `col42`..`col50`) — Access es case-insensitive, pero mantener el nombre exacto al leer es posible vía enumeración de Fields.

## T-006 — POC introspección de BD/DatosSERIEBM2025.mdb (PD-PLAN-05) ✅

**Script:** `poc/com_lee_tipos.php` · **Estado:** PASÓ

1. Abre la base real (6,4 MB) en **modo solo lectura** (`Mode = 1 adModeRead`).
2. Hash SHA-256 pre/post idéntico (`ab407732…`) → **original intocado**.
3. `OpenSchema(4)` sobre tabla `Datos`: 56 columnas, **idénticas en definición a la plantilla MASTER** (`Ano` Long, `CodigoPrestacion` VarChar(50), `Col01..Col50` Double prec 15 nullable, `fechaIngreso` adDate, `IdEstablecimiento` VarChar(7), `Mes` Long) — salvo `IdServicio` que aquí es **Long**.
4. Muestra de primera fila: `Col01=87.0` (double), `Col02=0.0`, `Col04..Col50=NULL`, `Mes=1` — tipos llegan a PHP como `double`/`integer`/`NULL` según corresponda.
5. JSON completo en `storage/rem/poc/datosseriebm2025_columnas.json` → **insumo directo de PD-PLAN-05** para las migraciones de FASE B.

### Conclusión PD-PLAN-05 (tipos MySQL sugeridos para `datos`)

- `Col01..Col50` → `DECIMAL(15,4)` en MySQL (el motor ACE declara Double con "prec=15"; los valores REM son numéricos con hasta 4 decimales según umbrales de redondeo RN-018; se definirá con la regla de redondeo de SPECS).
- `Mes`/`Ano`/`IdServicio` (base serie) → `INT`; `IdServicio` en el archivo Minsal → `CHAR(2)`.
- `CodigoPrestacion` → `VARCHAR(50)`; `IdEstablecimiento` → `CHAR(7)`; `fechaIngreso` → `DATETIME`.

## T-007 — POC SoapClient contra el WSDL Minsal ✅

**Script:** `poc/soap_minsal.php` · **Estado:** PASÓ (2026-10-26, sesion 3)

1. `SoapClient` sobre `https://cargasrem.minsal.cl/webservice/webservicedb.asmx?WSDL` con `trace=1`, `exceptions=1`, `connection_timeout=10`, `timeout=30`, `cache_wsdl=WSDL_CACHE_NONE`, compresión GZIP verificada. WSDL descargado en 0.76 s.
2. Operaciones expuestas: `datos`, `servicio`, `diccionario`, `Thoja`, `Version`, `Excep`, `ColExcep` (parametro `$parameters` tipo objeto vacío).
3. Llamadas reales: `Version` → **168 KB, 0.69 s**; `servicio` → **7.9 KB, 0.1 s**, ambas como `stdClass` (DataSet ASMX). Fixtures crudos (request+response) en `poc/fixtures/minsal/`.

### Hallazgos T-007

- El **DataSet** ASMX llega como `<{tabla} diffgr:id="…" msdata:rowOrder="…">` dentro de `diffgr:diffgram`: el nombre del elemento fila es el de la **tabla** (`idservicio`, `version`…), no el de la operación.
- `/servicio` (SOAP) trae 30 filas del maestro de servicios nacionales; `/Version` trae las **941 versiones históricas** del formato desde 2014 (mes, ano, version, Serie, SerieExcel) — mapa SerieExcel ↔ Serie interna disponible en el servidor Minsal.
- Los métodos ASMX **distinguen mayúsculas/minúsculas** también en SOAP binding (`Thoja`, `Version` capitalized).
- TLS y latency desde el Servicio de Salud Osorno: sin problemas (sin proxy requerido).

## T-008 — POC GET HTTP + SimpleXML ✅

**Script:** `poc/get_xml_minsal.php` · **Estado:** PASÓ (2026-10-26, sesion 3)

Guzzle 7.16 con `timeout=30` / `connect_timeout=10` + SimpleXML sobre los bindings HTTP GET de `webservicedb.asmx`:

| Endpoint (GET) | Registros | Tiempo | Bytes | Fixture |
|---|---|---|---|---|
| `/servicio` | **30** servicios (IdServicio, NServicio, IdRegion, Orden, ElimID) | 0.51 s | 9.9 KB | `servicio_get.xml` (completo) |
| `/Version` | **939** versiones (mes, ano, version, Serie, SerieExcel) | 0.27 s | 230 KB | `version_get.xml` (completo) |
| `/datos` | **3.205** establecimientos (IdEstablecimiento, NEstablecimiento, Direccion, Telefono, …) | 1.08 s | 2.1 MB | `datos_get_recorte.xml` (recorte 20 filas) |

Parseo: `simplexml_load_string` + XPath `//*[@msdata:rowOrder]` (con `registerXPathNamespace` para `msdata` ya que el prefijo se declara en nodos internos, no en la raíz). La via GET devuelve el **mismo DataSet** que SOAP, sin envelope.

### Hallazgos T-008

- **Confirmación de la vía primaria HTTP GET + XML** (decisión §229 de WebCargaREM.md): sin extensión SOAP, con respaldo SOAP ya evidenciado en T-007.
- Los bindings GET requieren nombre **exacto** de método ASMX (`/Version` en mayúscula; un error de nombre devuelve **HTTP 500** con el mensaje "Nombre de método no válido").
- Recorte de fixtures vía DOMXPath con `registerNamespace('msdata', …)`.
- Armadura patrón para RN-029 (sync catálogos): GET + `//*[@msdata:rowOrder]` + mapeo tabla→array.
- Buenas señales de red: `/datos` completo (2.1 MB) trae 1.9s — latencia estable para descargas nocturnas del sync.
